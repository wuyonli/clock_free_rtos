# clock_free_rtos — 基于 STM32 + FreeRTOS 的电子钟

一个运行在 **STM32F103RCT6** 上的桌面电子钟，使用 **FreeRTOS** 多任务调度，通过 **TM1637** 四位数码管显示时间，**DS1302** 掉电保持，支持 **ESP8266 网络校时** 与 **红外遥控调时**。

工程由 **STM32CubeMX** 生成，**STM32CubeIDE** 编译烧录，**VS Code** 编辑业务代码。

## 功能特性

- ⏰ **HH:MM 时间显示**：TM1637 四位数码管，冒号 500ms 闪烁
- 🌐 **ESP8266 网络校时**：通过串口接收 `YYYY-MM-DD HH:MM:SS` 时间字符串，自动解析并校准
- 🔋 **DS1302 掉电保持**：电池供电的实时时钟芯片，断网/断电后时间不丢，作为兜底时间源
- 📡 **红外遥控调时**：HX1838 红外接收 + NEC 协议解码，遥控器即可调时/调分/清零秒，或一键同步网络时间到 DS1302
- 💡 **双 LED 闪烁**：演示 FreeRTOS 多任务并发
- 🗓️ **每日自动校准**：每天 23:50 用网络时间同步一次 DS1302

## 时间源策略

时钟任务 `StartClockTask` 采用 **双时间源 + 每日校准** 的设计：

1. **网络时间优先**：若 3 秒内收到过 ESP8266 发来的时间，直接使用网络时间显示。
2. **DS1302 兜底**：网络超时则回退到 DS1302 芯片内部走时。
3. **每日自动校准**：当网络时间到达 **23:50** 时，把完整时间（含星期，用 Sakamoto 算法计算）写回 DS1302，保证掉电期间 RTC 也保持准确。
4. **红外调时**：仅当 DS1302 作为显示源时生效（网络在线时以网络为准，调了也会被覆盖）。

```
                    ┌────────────────────┐
                    │ ESP 3s 内有数据？   │
                    └───────┬────────────┘
                   是 │          │ 否
              ┌────────▼───┐  ┌───▼──────────────┐
              │ 用 ESP 时间 │  │ 用 DS1302 时间    │
              │ (网络优先)  │  │ (+ 红外按键调时)  │
              └────────────┘  └──────────────────┘
```

## 红外遥控按键

红外接收使用 **NEC 协议**（地址码 0x00，带反码校验）。当前映射了遥控器的四个按键：

| 按键 | NEC 命令码 | 功能 |
|------|-----------|------|
| 按键 1 | `0xA2` | 小时 +1（到 24 归零） |
| 按键 2 | `0x62` | 分钟 +1（到 60 归零） |
| 按键 3 | `0xE2` | 秒清零 |
| 按键 4 | `0x22` | 同步网络时间到 DS1302（仅 3 秒内收到过网络时间） |

> 完整的 NEC 键码表（`0x22`/`0x02`/`0xC2`/`0xE0`/`0xA8`/`0x90`/`0x98` 等）已定义在 [Core/Inc/hx1838.h](Core/Inc/hx1838.h) 中，可按需扩展。
>
> 重复码（长按）会被忽略，只响应单次按下。

## FreeRTOS 任务

| 任务 | 函数 | 优先级 | 栈大小 | 周期 | 说明 |
|------|------|--------|--------|------|------|
| `LED_Task` | `StartLedTask` | Idle (-3) | 128 words | 500ms | PB5 翻转 |
| `LED2_Task` | `StartLed2Task` | Idle (-3) | 128 words | 250ms | PB6 翻转 |
| `clockTask` | `StartClockTask` | Normal (0) | 128 words | 100ms | 主时钟任务 |

> 前两个任务由 CubeMX 生成在 `freertos.c`；`clockTask` 在 `main.c` 手动创建。FreeRTOS 接口为 **CMSIS_V1**，版本 **V10.3.1**。
>
> SysTick 被 FreeRTOS 占用，HAL 时基改用 **TIM2**。

## 构建与烧录

### 方式一：STM32CubeIDE（推荐）

1. 用 STM32CubeIDE 打开工程根目录（导入 `.project`）。
2. 确认 C/C++ Build 的 Builder 为 **Gnu Make Builder**（工程是 CubeIDE 原生构建，非 CMake）。
3. 点击 **Build** 编译。
4. 通过 ST-Link / SWD 连接后点击 **Run** / **Debug** 烧录。

### 方式二：CubeMX 重新生成

若修改了 `clock_free_rtos.ioc`，回到 CubeMX 点 **GENERATE CODE** 重新生成，然后回 CubeIDE 编译。

> ⚠️ 重新生成会覆盖非 `USER CODE` 区的代码。**业务逻辑必须放在 `/* USER CODE BEGIN/END */` 之间**。

## 关键实现细节

### 1. DS1302（GPIO 模拟三线时序）

- CLK / RST / DAT 三线，DAT 为**双向**：写入时切 `GPIO_MODE_OUTPUT_PP`，读取时切 `GPIO_MODE_INPUT`（带上拉）。
- 微秒延时基于 **DWT 周期计数器**（`CoreDebug->DEMCR` + `DWT->CYCCNT`），无需占用定时器。
- 数据为 **BCD 编码**，读写时做 BCD ↔ 十进制转换。
- 首次上电检测：读秒寄存器 Bit7 为 1（芯片未走时）则写入默认时间。

### 2. HX1838（TIM3 输入捕获 + NEC 解码状态机）

- TIM3 通道 3（PB0）配置为**下降沿输入捕获**，预分频 71 → 1µs 计数。
- 状态机识别：`9ms 低 + 4.5ms 高` 起始帧 → 32 位数据（地址 + 地址反码 + 命令 + 命令反码）。
- 逻辑 0 ≈ 1120µs，逻辑 1 ≈ 2250µs。
- 收到 32 位后做 **NEC 反码校验**（`addr ^ addr_inv == 0xFF` 且 `cmd ^ cmd_inv == 0xFF`），通过才回调 `HX1838_OnReceive`。

### 3. ESP8266 串口校时

- USART3 以中断方式**逐字节接收**，攒成一行（以 `\n` 结束，忽略 `\r`）。
- 收到完整一行后置 `uart_line_ready`，由 `clockTask` 在任务上下文解析。
- 支持格式：`YYYY-MM-DD HH:MM:SS`（≥19 字符），带分隔符位置校验和数值范围校验。

### 4. 中断优先级分配

| 中断 | 优先级 |
|------|--------|
| USART3 | 5 |
| TIM3 | 5 |
| TIM2（时基） | 15 |
| SysTick / PendSV | 15 |

> 中断回调（`HAL_UART_RxCpltCallback`、`HAL_TIM_IC_CaptureCallback`）中只做轻量操作，重逻辑放到任务里。

## 常见坑与注意

1. **F1 输入引脚必须用 `GPIO_MODE_INPUT`，不是 `AF_PP`**。若 PB0（红外）或 PB11（串口 RX）误配成 `AF_PP`，引脚会被拉低，信号进不来 —— 红外一帧都收不到。这是 STM32F1 与 F4/F0 系列的典型差异。

2. **业务代码务必放 `USER CODE` 区**，否则 CubeMX 重生成会覆盖。

3. **SysTick 已被 FreeRTOS 占用**，HAL 时基改用 TIM2（CubeMX 里配 Timebase=TIM2）。

4. **PA4（DS1302 DAT）是双向引脚**：CubeMX 里只配成输出作初始态，驱动运行时用 `DS1302_DAT_Output()/Input()` 动态切换方向。

5. **ESP8266 只接了 RX（PB11）**，本工程只接收时间，不回传。
